# Алгоритмы и структуры данных. Лекция 4: рекурсия и Merge Sort

> [!info] Связь с другими конспектами
> Продолжение [[АиСД - Лекция 3 - Решето Эратосфена и квадратичные сортировки|лекции 3]]. Указатели и массивы из этой лекции (`arr + left`) — это [[C++ - Лекция 4 - Массивы|арифметика указателей из C++]].

---

## I. Зачем нужна быстрая сортировка

`BubbleSort`, `InsertionSort`, `SelectionSort` — все работают за $T(N) = O(N^2)$.

При $N \sim 10^6$: $10^{12}$ операций; при скорости $10^8$ операций/сек это $\dfrac{10^{12}}{10^8} = 10^4$ секунд (почти три часа). Нужен алгоритм быстрее — **Merge Sort**. Но для него сначала нужна рекурсия.

---

## II. Рекурсия

**Рекурсия** — вызов функции **из самой себя**.

### Пример: факториал

$$n! = 1\cdot2\cdot3\cdots n$$

**Определение:**
- $n = 0 \implies 0! = 1$ (по определению, аксиома)
- $\forall n \in \mathbb{N}:\ n! = (n-1)!\cdot n$

Например: $5! = 5\cdot4! = 5\cdot(4\cdot3\cdot2\cdot1)$.

**Функция:**

```
factorial(n):
    если n == 0:
        return 1
    return n * factorial(n - 1)
```

**Как «раскручивается» вызов:**

$$f(n) = n\cdot f(n-1) = n\cdot(n-1)\cdot f(n-2) = n(n-1)(n-2)\cdot f(n-3) = \dots$$
$$= n(n-1)\cdots 2 \cdot 1 \cdot f(0) = n(n-1)\cdots 1\cdot 1 = n!$$

$$T(N) = O(N)$$ (ровно $N$ вложенных вызовов).

### Виды рекурсии

| Вид | Аргумент | Пример | Результат |
|---|---|---|---|
| **нисходящая** | уменьшается | $f(n) = f(n-1)\cdot n$, $f(0)=1$ | $n!$ |
| **восходящая** | увеличивается | $f(n) = 2\cdot f(n+1)$, $f(10)=1$ | $2^k$ (где $k = 10 - n$) |

В обоих случаях нужно **граничное условие** (базовый случай) — значение, при котором рекурсия **останавливается** (здесь $f(0) = 1$ или $f(10) = 1$). Это как лестница, упирающаяся в пол: идём вниз по ступенькам, пока не дойдём до границы.

> [!warning] Без базового случая рекурсия бесконечна
> Если забыть граничное условие (или никогда его не достичь), функция будет вызывать сама себя, пока не закончится память стека — программа упадёт.

## III. Функция Merge (слияние)

**Задача:** есть **два отсортированных** массива `A` и `B`; нужно слить их в один отсортированный массив `C`.

**Идея:** заводим два «указателя» — `L` на текущий элемент `A` и `R` на текущий элемент `B`. На каждом шаге сравниваем `A[L]` и `B[R]`, меньший кладём в `C` и сдвигаем соответствующий указатель.

- размер результата: `C.size = A.size + B.size`
- куда класть очередной элемент: `id = L + R` (сколько элементов уже переложили)

**Алгоритм:**

```
Merge(A, B, lenA, lenB, result):
    L = R = 0
    пока (L < lenA и R < lenB):
        если A[L] ≤ B[R]:                // ≤ — для устойчивости
            result[L + R] = A[L]
            L++
        иначе:
            result[L + R] = B[R]
            R++
    пока (L < lenA):                     // остаток A
        result[L + R] = A[L]
        L++
    пока (R < lenB):                     // остаток B
        result[L + R] = B[R]
        R++
```

> [!important] Почему `≤`, а не `<`
> Если при равенстве брать элемент из `A` (левого массива), то равные элементы сохраняют исходный порядок, и сортировка получается **устойчивой**. Если поставить строгое `<`, равные из `B` обгонят равные из `A`.

**Асимптотика.** Пусть $N = L + R = \text{lenA} + \text{lenB}$:
$$T(N) = O(N), \qquad M(N) = O(1)$$

(дополнительной памяти почти не тратим — массивы `A`, `B`, `result` созданы **не нами**, а переданы снаружи).

## IV. Разговор про память: Merge прямо на одном массиве

В Merge Sort оба «массива» — это просто **два соседних куска одного** массива `arr`:

```
arr:  | left ........... M ........... right |
         └──── A ────┘   └──── B ────┘
```

Две области (через арифметику указателей):

```cpp
int* A = arr + left;     // lenA = M - left
int* B = arr + M;        // lenB = right - M
```

Полуинтервалы: $A \to [\text{left};\, M)$, $B \to [M;\, \text{right})$ (правая граница **не включается**).

**Функция слияния кусков массива:**

```
Merge(arr, left, M, right, result):
    // A → [left; M),  B → [M; right),  итог кладём в arr
    L = R = 0
    A = arr + left
    B = arr + M
    пока (L < lenA и R < lenB):
        если A[L] ≤ B[R]:
            result[L + R] = A[L]; L++
        иначе:
            result[L + R] = B[R]; R++
    пока (L < lenA): result[L + R] = A[L]; L++
    пока (R < lenB): result[L + R] = B[R]; R++

    for i = 0 ... (L + R):
        arr[i + left] = result[i]       // копируем слитый результат обратно в arr
```

(Здесь `lenA = M - left`, `lenB = right - M`.) Слияние идёт во вспомогательный массив `result` (буфер), а затем результат копируется обратно на место исходных двух кусков.

## V. Merge Sort

**Идея «разделяй и властвуй»:**

1. **Делим** массив пополам, потом каждую половину снова пополам, и т.д. — пока не получим $N$ массивов длины 1 (а массив из одного элемента уже отсортирован)
2. **Сливаем** обратно парами через Merge: отсортированные куски длины 1 → длины 2 → длины 4 → … → весь массив

```
N                       ← весь массив
N/2        N/2
N/4  N/4  N/4  N/4
...                      ← k делений
1  1  1 ... 1  1         ← N массивов
        ↓ слияния (Merge) ↓
...                     
весь массив, отсортированный
```

**Сколько уровней.** Размер куска после $k$ делений: $\dfrac{N}{2^k} = 1 \implies k = \log_2 N$.

На **каждом** уровне суммарно обрабатывается $N$ элементов (Merge за $O(N)$ на уровень), уровней $\log_2 N$:

$$T(N) = O(\log_2 N\cdot N) = O(N\log N)$$

## VI. Рекурсивная часть и итоговая функция

**Рекурсивная функция** — сортирует кусок `arr[left; right)`:

```
recursiveMergeSort(arr, left, right, buffer):
    // надо отсортировать arr[left; right)
    если right - left == 1:         // в куске один элемент — уже отсортирован
        return
    M = (right + left) / 2          // или M = left + (right - left) / 2
    recursiveMergeSort(arr, left, M, buffer)
    recursiveMergeSort(arr, M, right, buffer)
    Merge(arr, left, M, right, buffer)
    return
```

**Обёртка:**

```
MergeSort(arr, N):
    buffer = [...]                  // размера N
    recursiveMergeSort(arr, 0, N, buffer)
    delete buffer
```

> [!tip] Базовый случай и обёртка
> Базовый случай `right - left == 1` — именно то граничное условие из раздела II: рекурсия останавливается, когда в куске остался один элемент. Буфер создаётся **один раз** в обёртке (а не внутри рекурсии), поэтому дополнительная память $O(N)$ выделяется единожды. `delete buffer` — освобождение динамической памяти (см. `new[]`/`delete[]` в [[C++ - Лекция 4 - Массивы|лекции про массивы]]).

> [!warning] Дополнение от меня: пустой массив
> Для $N = 0$ условие `right - left == 1` никогда не выполнится (разность $0$), и рекурсия станет бесконечной. На практике добавляют проверку `если right - left ≤ 1: return`.

### Итог по Merge Sort

| Характеристика | Значение |
|---|---|
| время $T(N)$ | $O(N\log N)$ |
| дополнительная память $M(N)$ | $O(N)$ (буфер) |
| устойчивость | **да** (благодаря `≤` в Merge) |

## VII. Теорема о нижней границе (без доказательства)

> [!important] Теорема
> **Никакая сортировка, основанная на сравнениях, не может работать быстрее, чем $\Omega(N\log N)$.**

То есть Merge Sort в этом смысле оптимален по порядку роста.

**Сравнение на $N \sim 10^6$** (скорость $10^8$ операций/сек):

| Алгоритм | Операций | Время |
|---|---|---|
| квадратичные ($O(N^2)$) | $10^{12}$ | $10^{12}/10^8 = 10^4$ сек (около 3 часов) |
| Merge Sort ($O(N\log N)$) | $10^6\cdot\log_2 10^6 \approx 10^6\cdot20 = 2\cdot10^7$ | $2\cdot10^7/10^8 = 0{,}2$ сек |

Разница — в 50 000 раз.

---

## Итог лекции

- **Рекурсия** — функция вызывает саму себя; обязательно нужен **граничный (базовый) случай**; бывает нисходящая (аргумент уменьшается) и восходящая (растёт)
- **Merge** сливает два отсортированных массива за $O(N)$, при `≤` — устойчиво
- **Merge Sort** = «делим пополам до одиночных элементов» + «сливаем обратно»: $T(N) = O(N\log N)$, $M(N) = O(N)$, **устойчивая**
- Сортировки сравнением не могут быть быстрее $\Omega(N\log N)$, так что Merge Sort — оптимальный по порядку алгоритм
- Для $N = 10^6$ выигрыш по сравнению с квадратичными сортировками — с трёх часов до 0,2 секунды
