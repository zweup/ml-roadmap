# Алгоритмы и структуры данных. Лекция 2: простейшие алгоритмы

> [!info] Связь с другими конспектами
> Продолжение [[АиСД - Лекция 1 - Время работы, оценки сложности, асимптотика|лекции 1]] — здесь сложность считаем уже на конкретных алгоритмах. Дальше: [[АиСД - Лекция 3 - Решето Эратосфена и квадратичные сортировки|лекция 3]].
> Обозначения: $T(N)$ — время работы, $M(N)$ — дополнительная память. В псевдокоде `a : b` значит «a делится на b».

## I. Поиск простых делителей (разложение на простые множители)

**Идея:** перебираем $d = 2, 3, 4, \dots$; если $N$ делится на $d$ — выписываем $d$ и делим $N$ на $d$; если нет — увеличиваем $d$.

Примеры:

```
30 | 2     ← 30 : 2  → 15
15 | 2     ← 15 не делится на 2, пробуем дальше (вычёркиваем)
15 | 3     ← делится → 5
 5 | 3     ← не делится
 5 | 4     ← не делится
 5 | 5     ← делится → 1
 1

30 = 2 · 3 · 5
```

```
24 | 2
12 | 2
 6 | 2
 3 | 3
 1

24 = 2 · 2 · 2 · 3
```

**Алгоритм:**

```
число N — на простые множители
d = 2
пока (N ≠ 1):
    если N : d:
        N = N / d
        вывести(d)
    иначе:
        d = d + 1
```

**Асимптотика:** $T(N) = O(N)$ — линейная, $M(N) = O(1)$.

> [!tip] Почему именно $O(N)$
> Худший случай — когда $N$ простое: тогда $d$ дойдёт до самого $N$. Заметь, что составной $d$ никогда не «сработает»: к моменту, когда $d$ составное, все его простые множители уже вынесены из $N$.

> [!tip] Дополнение от меня: как ускорить
> Если после перебора до $\sqrt N$ в $N$ что-то осталось (больше 1), то это оставшееся число само простое. Тогда $T(N) = O(\sqrt N)$ — та же идея, что в проверке на простоту из лекции 1.

## II. Наибольший общий делитель (НОД)

**Определение:** $\text{НОД}(a, b) = k$, если $a \,\vdots\, k$, $b \,\vdots\, k$ и $k$ — максимальное из таких чисел.

Пример через разложение на простые:
$$24 = 2\cdot2\cdot\underline{2\cdot3}, \qquad 30 = \underline{2\cdot3}\cdot5 \implies \text{НОД}(24,30) = 2\cdot3 = 6$$

(берём общие простые множители). Но раскладывать на множители долго, поэтому есть алгоритм Евклида.

### а) Алгоритм Евклида, тип 1 (вычитанием)

**Свойства:**
- $\text{НОД}(a, b) = \text{НОД}(b, a)$
- $\text{НОД}(a, b) = \text{НОД}(a,\, b-a)$, если $b \ge a$
- $\text{НОД}(a, 1) = 1$, $\text{НОД}(a, 0) = a$

**Доказательство второго свойства.** Надо показать, что у пар $(a, b)$ и $(a, b-a)$ **одинаковые наборы общих делителей** — тогда одинаков и максимальный.
- Если $k$ делит $a$ и $b$, то $k$ делит и разность $b - a$.
- Если $k$ делит $a$ и $b - a$, то $k$ делит и их сумму $(b-a) + a = b$.

Значит, $k_1$ (максимальный делитель для $a, b$) и $k_2$ (максимальный для $a, b-a$) совпадают. $\blacksquare$

**Пример:**

$$\text{НОД}(124, 24) = \text{НОД}(100, 24) = \text{НОД}(76, 24) = \text{НОД}(52, 24) = \text{НОД}(28, 24) = \text{НОД}(4, 24) =$$
$$= \text{НОД}(4, 20) = \text{НОД}(4, 16) = \text{НОД}(4, 12) = \text{НОД}(4, 8) = \text{НОД}(4, 4) = \text{НОД}(0, 4) = 4$$

**Алгоритм:**

```
НОД(a, b),  a, b ∈ N
пока a ≠ 0 и b ≠ 0:
    если a > b:
        a = a - b
    иначе:
        b = b - a
вывести(a + b)       // одно из чисел равно 0, второе — ответ
```

**Асимптотика:** $T(a, b) = O(a+b) = O(\max(a, b))$.

### б) Алгоритм Евклида, тип 2 (с остатком) — быстрее

В примере выше мы много раз подряд вычитаем одно и то же число (например, 24 из 124). Это **то же самое, что взять остаток**:

$$124 - 24 - 24 - 24 - 24 - 24 = 4 = 124 \bmod 24$$

**Вывод:** $\text{НОД}(a, b) = \text{НОД}(a,\ b \bmod a)$ при $b > a$ — **работает быстрее**.

**Алгоритм:**

```
пока a ≠ 0 и b ≠ 0:
    если a > b:
        a = a % b
    иначе:
        b = b % a
вывести(a + b)
```

**Асимптотика:** $T(a, b) = O\big(\log(\max(a, b))\big)$ (без доказательства).

> [!important] Сравни тип 1 и тип 2
> Для $a = 10^{12}$ и $b = 1$ вычитание делало бы $10^{12}$ шагов, а остаток — один. Вся разница между $O(\max(a,b))$ и $O(\log \max(a,b))$ сводится к замене «вычитать много раз» на «взять остаток».

## III. Поиск `key` в массиве (линейный)

Дан массив `arr`, нужно проверить, есть ли в нём `key` (и вывести индекс).

```
arr = [1, 2, 17, 31, ...]      индексы: 0 1 2 3 ...     (arr[3] = 31)
```

```
flag = False
for i = 0 ... N:
    если arr[i] == key:
        flag = True
        вывести(i)
        break
если flag == False:
    вывести("не нашёл")
```

**Асимптотика:** $T(N) = O(N)$, $M(N) = O(1)$.

---

## IV. Бинарный поиск

**Задача та же, но массив отсортирован:** $a[0] \le a[1] \le \dots \le a[N-1]$.

**Идея:** смотрим на элемент в середине `arr[M]`:
- `key < arr[M]` ⟹ искать нужно в **левой** половине
- `key > arr[M]` ⟹ искать нужно в **правой** половине

Каждый шаг отбрасывает половину массива.

**Алгоритм:**

```
arr = [...]
L = 0
R = N - 1
пока (R - L > 1):
    M = (L + R) / 2          // в C++ лучше: M = L + (R - L) / 2
    если arr[M] > key:
        R = M
    иначе если arr[M] < key:
        L = M
    иначе:
        L = M
        break
если arr[L] == key или arr[R] == key:
    вывести("нашли")
иначе:
    вывести("не нашли")
```

> [!tip] Почему `M = L + (R - L) / 2`
> В C++ сумма `L + R` для больших индексов может **переполнить** `int` (а это UB, как в лекции 1 по C++). Формула `L + (R - L) / 2` даёт то же число, но без переполнения.

> [!tip] Зачем проверка в конце
> Цикл останавливается, когда между `L` и `R` не осталось элементов (`R - L ≤ 1`) — «подозреваемых» остаётся два: `arr[L]` и `arr[R]`, их и проверяем.

**Асимптотика.** Длина рассматриваемого участка по шагам:

| Шаг | Длина участка |
|---|---|
| 0 | $N$ |
| 1 | $N/2$ |
| 2 | $N/4$ |
| 3 | $N/8$ |
| $k$ | $N/2^k$ |

Останавливаемся, когда остался 1 элемент: $1 = \dfrac{N}{2^k} \implies 2^k = N \implies k = \log_2 N$.

$$T(N) = O(\log N)$$

### Сравнение на больших числах

Пусть $N \sim 10^{12}$, компьютер делает $10^8$ операций в секунду:

| Алгоритм | Итераций | Время |
|---|---|---|
| линейный поиск $O(N)$ | $10^{12}$ | $\approx 10^4$ сек (почти 3 часа) |
| бинарный поиск $O(\log N)$ | $\log_2 10^{12} \approx 40$ | $\approx \dfrac{40}{10^8}$ сек |

> [!important] Цена быстрого поиска
> Бинарный поиск работает **только на отсортированном** массиве. Чтобы отсортировать, придётся потратить время — этому посвящены лекции 3 и 4.

## V. Бинарный поиск по ответу

**Различие:**
- обычный бинарный поиск — ищем число **в массиве**
- по ответу — ищем число, но **в функции**: вместо `arr[x]` у нас `f(x)`, причём `f` **монотонная** (только растёт или только убывает)

То есть `arr[x]` ⟷ `f(x)`: те же `L`, `R`, `M` на оси $x$, только значение «элемента» вычисляется функцией, а не берётся из памяти.

### Пример на дробных числах: найти $\sqrt N$

Нужно найти $M = \sqrt N$, то есть такое $M$, что $M^2 = N$. Функция $f(x) = x^2$ монотонно растёт, а искомый корень лежит в отрезке $[0;\, N]$.

**Вариант 1 — пока не достигнем точности $\varepsilon$:**

```
float L = 0, R = N
eps = 1e-5
пока (|L * L - N| > eps):
    M = (L + R) / 2
    если M * M < N:
        L = M
    иначе:
        R = M
```

**Вариант 2 — гарантированное число итераций:**

```
float L = 0, R = N
for i = 0 ... 1000:
    M = (L + R) / 2
    если M * M < N:
        L = M
    иначе:
        R = M
```

> [!tip] Зачем второй вариант
> У первого число итераций заранее неизвестно, и при слишком маленьком `eps` он вообще может **не завершиться** (из-за ограниченной точности дробных чисел — см. лекцию 1 по C++, про `0.1 + 0.2`). Второй всегда делает ровно 1000 шагов — этого хватает с огромным запасом, ведь отрезок сжимается вдвое на каждом.

> [!warning] Дополнение от меня: два тонких места
> 1. В конспекте стоит вопрос «почему $\sqrt N \in [0; N]$?». Это верно при $N \ge 1$ (тогда $\sqrt N \le N$). Для $0 < N < 1$ корень **больше** $N$, и правую границу надо брать, например, $R = \max(1, N)$.
> 2. В реальном коде лучше брать `double`, а не `float`: у `float` слишком мало значащих цифр, и условие $|L\cdot L - N| \le \varepsilon$ может не достигаться.

---

## Итог лекции

- **Простые множители** — перебор $d$ и деление, $T(N) = O(N)$ (можно ускорить до $O(\sqrt N)$)
- **НОД** — алгоритм Евклида: вычитанием $O(\max(a,b))$, с остатком $O(\log \max(a,b))$
- **Линейный поиск** — $O(N)$, работает на любом массиве
- **Бинарный поиск** — $O(\log N)$, но только на **отсортированном** массиве; идея «отбрасываем половину»
- **Бинарный поиск по ответу** — тот же приём, но вместо массива **монотонная функция** (пример: корень $\sqrt N$)
