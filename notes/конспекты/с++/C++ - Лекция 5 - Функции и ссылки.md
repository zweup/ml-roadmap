## 1. Функции

### 1.1. Зачем давать фрагменту программы имя

Если одно и то же действие нужно в разных местах (найти меньшее из двух, ввести массив), его выделяют в **функцию**. У функции есть:

- **имя**
- **параметры** (через них приходят исходные данные)
- **тело** (инструкции)
- **возвращаемое значение** (если функция что-то вычисляет)

```cpp
int Min(int x, int y) {
    return x < y ? x : y;
}
```

`int` слева — тип результата, `Min` — имя, `(int x, int y)` — два параметра, в `{}` — тело. Выражение `x < y ? x : y` выбирает одно из значений: если `x < y` — `x`, иначе `y`.

Общий вид:

```cpp
ReturnType FunctionName(Type1 parameter1, Type2 parameter2, ...) {
    // function body
}
```

> [!tip] Стиль курса
> Имена своих функций начинаем с **заглавной** буквы (`Min`) — это соглашение об оформлении, а не требование языка. А вот `main` пишется строчными и переименовать её нельзя: с неё компьютер начинает выполнение.

### 1.2. Как вызвать функцию

Определение само по себе тело **не запускает** — нужен **вызов**: имя и круглые скобки со значениями.

```cpp
int value = Min(10, 20);          // 10
std::cout << Min(10, 20) << '\n'; // результат сразу в поток вывода
```

- **Аргументы** — выражения в вызове (`10`, `20`, `a + 5`)
- **Параметры** — переменные в заголовке определения (`x`, `y`)
- Типы перед аргументами при вызове заново **не пишутся**

> [!warning] `main` вызывать из своего кода нельзя
> Это запрещено стандартом. Если какой-то компилятор пропустил такой эксперимент без ошибки, программа от этого корректной не стала.

## 2. Объявление и определение функции

### 2.1. Что нужно знать компилятору в месте вызова

Чтобы вызвать функцию, компилятору не обязательно видеть её **тело** — достаточно знать, что она существует и как с ней обращаться. Для этого служит **объявление** (без тела, с `;`):

```cpp
int Min(int x, int y);          // объявление

int main() {
    std::cout << Min(10, 20) << '\n';
    return 0;
}

int Min(int x, int y) {         // определение
    return x < y ? x : y;
}
```

Определение тоже является объявлением, поэтому когда оно стоит **выше** вызова, отдельное объявление не нужно.

Если вызов стоит выше всех объявлений — **ошибка компиляции**: компилятор не станет искать функцию дальше по файлу.

```cpp
int main() {
    return Min(10, 20);         // CE: Min is not declared here
}
int Min(int x, int y) { ... }
```

### 2.2. Имена параметров в объявлении

В объявлении нужны только **типы**, имена можно опустить — это три записи **одной** функции:

```cpp
int Min(int x, int y);
int Min(int, int);
int Min(int x, int);
```

В **определении** имена нужны, если мы используем параметры в теле. Имена параметров относятся к самой функции: в вызывающем коде переменные могут называться как угодно (создавать `x` и `y` в `main` не нужно).

### 2.3. Сигнатура функции

Сигнатура обычной функции = **имя + типы параметров** (+ пространство имён): `Min(int, int)`.

- **Возвращаемый тип** в сигнатуру **не входит** (но объявление и определение должны согласованно его описывать). Две функции нельзя различить только типом результата:
  ```cpp
  int Min(int, int);
  float Min(int, int);     // CE: conflicting return types
  ```
- **Имена параметров** в сигнатуру не входят: `Min(int x, int y)` и `Min(int a, int b)` — одна функция.
- `const` у параметра, передаваемого **по значению**, на сигнатуру не влияет:
  ```cpp
  int Min(int x, int y);
  int Min(int x, const int y) { return x < y ? x : y; }   // та же функция Min(int, int)
  ```
  Здесь `const` лишь запрещает менять локальный `y` в теле (`y += 1;` — ошибка).

### 2.4. Объявлений может быть несколько, определение — одно

Согласованные объявления можно повторять. А два **определения** одной функции в одном файле — нельзя, даже с одинаковыми телами:

```cpp
int Min(int x, int y) { return x < y ? x : y; }
int Min(int x, int y) { return x > y ? x : y; }    // CE: redefinition
```

Это **ODR** (One Definition Rule): объявлений сколько угодно, определение с телом — одно.

> [!important] Объявил, вызвал, но не определил — ошибка компоновки
> Если объявить `Min`, вызвать её и так и не дать определения, сборка закончится **ошибкой компоновки** (линковщика), а не компиляции. Позже объявление и определение будут лежать в разных файлах.

## 3. Аргументы по умолчанию

Если написать `Min(5)`, компилятор не знает, что подставить во второй параметр. Можно задать значение по умолчанию **в объявлении**:

```cpp
int Min(int x, int y = 1);       // значение по умолчанию задано здесь

int main() {
    int first  = Min(5);         // 5 и 1 → результат 1
    int second = Min(10, 20);    // 10
    return 0;
}

int Min(int x, int y) {          // в определении "= 1" НЕ повторяем
    return x < y ? x : y;
}
```

Если задать значения для обоих параметров:

```cpp
int Min(int x = 0, int y = 1);

Min();          // x = 0, y = 1  → 0
Min(5);         // x = 5, y = 1  → 1
Min(10, 20);    // оба явно      → 10
```

### Какие аргументы можно опускать

Аргументы передаются **по порядку**; опускать можно только **последние**. Если у параметра есть значение по умолчанию, то у **всех следующих** оно тоже должно быть:

```cpp
int First(int x, int y);            // OK
int Second(int x, int y = 1);       // OK
int Third(int x = 0, int y = 1);    // OK
int Wrong(int x = 0, int y);        // CE
Min(, 20);                          // CE: пропустить середину нельзя
```

> [!warning] Где писать `= значение`
> Значение по умолчанию должно быть видно в **объявлении перед вызовом**. Если перед `main` стоит только `int Min(int, int);`, а `= 1` написано лишь в определении ниже, то вызов `Min(5)` в `main` — ошибка. Повторять то же значение в следующем объявлении или определении **нельзя** — даже такое же.

> [!important] Значение по умолчанию не создаёт новую функцию
> Функция по-прежнему **одна**, с двумя параметрами. Аргументы по умолчанию в сигнатуру не входят; тело всегда получает значения обоих параметров и не отличает `Min()` от `Min(0, 1)`.

## 4. Возврат из функции

### 4.1. Что делает `return`

`return` делает два действия: **завершает** текущий вызов и (если нужно) **передаёт результат** в место вызова. Это **не вывод на экран** — чтобы увидеть число, нужен отдельный `std::cout`.

Инструкций `return` может быть несколько — выполнится только та, до которой первой дойдёт управление:

```cpp
float Max(float x, float y) {
    if (x < y) {
        return y;      // сразу выходим из функции
    }
    return x;
}
```

### 4.2. Нельзя забывать результат на одном из путей

```cpp
float Max(float x, float y) {
    if (x < y) {
        return y;
    }
}   // UB, если выполнение дойдёт досюда
```

Для `Max(10, 4)` условие ложно, управление доходит до `}` без возврата — это **неопределённое поведение (UB)**. Нельзя считать, что вернётся ноль или последнее вычисленное число. Предупреждение компилятора здесь нужно **исправлять**, а не игнорировать (на лекции программа упала с `Illegal instruction` — но это лишь одно из возможных проявлений).

> [!tip] Правило
> Каждый путь, нормально завершающий функцию с возвращаемым значением, обязан привести к корректному `return`. Исключение — только `main`: достижение её конца равносильно `return 0;`.

### 4.3. Функции без возвращаемого значения (`void`)

```cpp
void PrintHelloWorld();                // нет параметров — пустые скобки

int main() {
    PrintHelloWorld();                 // скобки в вызове убирать нельзя
    return 0;
}

void PrintHelloWorld() {
    std::cout << "Hello, world!\n";
}
```

- `void`-функция завершается, дойдя до конца тела, либо через `return;` (без выражения)
- вернуть число из неё нельзя
- `void` ≠ «ничего не делает» — просто у вызова нет значения, которым можно инициализировать переменную

### 4.4. Как управление возвращается в место вызова

Упрощённая модель: при вызове нужно передать аргументы, выполнить тело, получить результат и продолжить вызывающий код. Кроме результата нужен **адрес возврата** — место, откуда продолжать после функции.

Данные для одного вызова образуют **кадр стека вызовов (stack frame)**: адрес возврата, аргументы, локальные переменные, сохранённые регистры. При вложенном вызове поверх кадра создаётся новый, при возврате он освобождается. Но часть данных может идти через регистры — состав кадра зависит от платформы и оптимизаций.

> [!tip] Почему отсутствие `return` нельзя объяснять «читается какой-то регистр»
> Правило языка — UB при достижении конца такой функции; какая именно «мусорная» величина получится, зависит от платформы и оптимизаций.

## 5. Передача параметров по значению

**По значению** — функция получает **собственные переменные**, инициализированные значениями аргументов. Изменение параметров не меняет переменные в месте вызова.

```cpp
float Max(float x, float y) {
    x += 1;                  // меняем ЛОКАЛЬНЫЙ параметр
    if (x < y) return y;
    return x;
}

float a = 10;
float b = 4;
float result = Max(a, b);
std::cout << a << '\n';        // 10  (a не изменилась)
std::cout << b << '\n';        // 4
std::cout << result << '\n';   // 11
```

- Значение `a` скопировано в `x`, а `b` — в `y`; `x += 1` изменило копию
- Имена в вызывающем коде и в определении (`y` в `main` и параметр `y`) — **разные переменные**, совпадение имён их не связывает
- Целочисленные аргументы `10`, `4` преобразуются к `float` (типу параметров)
- Чтобы записать результат в `a`, нужно явное присваивание: `a = Max(a, b);`

## 6. Как изменить переменные вызывающей функции

### 6.1. Задача обмена значений

Есть `z = 1`, `v = 2`; хотим, чтобы после вызова стало `z = 2`, `v = 1`. В стандартной библиотеке такая функция уже есть — `std::swap` (из `<utility>`). Попробуем написать свою.

Обмен делается через **временную переменную**:

```cpp
float tmp = z;
z = v;
v = tmp;
```

Двумя присваиваниями обойтись нельзя: `z = v; v = z;` — после первой строки обе переменные равны старому `v`, значение `z` уже потеряно.

### 6.2. Почему `DummySwap` ничего не меняет снаружи

```cpp
void DummySwap(float lhs, float rhs) {
    float tmp = lhs;
    lhs = rhs;
    rhs = tmp;
}

float z = 1.0f, v = 2.0f;
DummySwap(z, v);
std::cout << z << ' ' << v << '\n';    // 1 2   — обмена не случилось
```

Алгоритм верный, но он меняет **копии** `lhs`/`rhs`. Объектов теперь четыре: `z`, `v` и два параметра. Снаружи остаётся прежняя пара.

> [!important] Присваивание параметру ≠ присваивание аргументу
> Одинаковые значения не делают два объекта одним объектом. Чтобы изменить `z` и `v`, функции нужно дать доступ **именно к ним**.

## 7. Передача адресов в функцию

### 7.1. `SwapByPointer`

```cpp
void SwapByPointer(float* lhs, float* rhs) {
    float tmp = *lhs;     // значение объекта по адресу lhs
    *lhs = *rhs;
    *rhs = tmp;
}

float z = 1.0f, v = 2.0f;
SwapByPointer(&z, &v);
std::cout << z << ' ' << v << '\n';    // 2 1
```

Передаём **адреса** (`&z`, `&v`); внутри разыменовываем (`*lhs`). Различай две операции:

```cpp
*lhs = *rhs;    // присвоить значение ОБЪЕКТУ, на который указывает lhs
lhs = rhs;      // присвоить ЛОКАЛЬНОМУ указателю (теперь оба указывают на один объект)
```

Вторая строка обмена значений **не** делает.

### 7.2. Указатель тоже передаётся по значению

Правило копирования не отменено: копируется **адрес**. Присвоить параметру-указателю другой адрес можно — вне функции это ничего не изменит; но разыменование копии адреса всё равно ведёт к тому же объекту:

```cpp
void SetZero(float* ptr) {
    *ptr = 0.0f;         // меняет объект снаружи
    ptr = nullptr;       // меняет только локальную копию указателя
}

float value = 7.0f;
float* address = &value;
SetZero(address);
std::cout << value << '\n';                 // 0
std::cout << (address == &value) << '\n';   // 1  (address не изменился)
```

> [!tip] Какой вопрос задавать
> Не только «копируется ли параметр?», но и «**к какому объекту мы обращаемся через этот параметр?**». Также: `SwapByPointer` сразу разыменовывает указатели, поэтому передавать ей `nullptr` нельзя.

### 7.3. `const` у указателя

В лекции параметры помечены как `float* const`:

```cpp
void SwapByPointer(float* const lhs, float* const rhs) { ... }
```

`const` **после звёздочки** относится к **самому указателю**: адрес менять нельзя, объект по адресу — можно.

```cpp
void Example(float* const ptr) {
    *ptr = 5.0f;        // OK
    ptr = nullptr;      // CE: сам ptr константный
}
```

Сравни:

```cpp
float* const fixed = &value;        // указатель константный, объект меняется
*fixed = 3.0f;                      // OK

const float* read_only = &value;    // объект через указатель не меняется
read_only = &other;                 // OK (указатель можно перенаправить)
// *read_only = 3.0f;               // CE
```

> [!important] Объявление и определение с `float* const` — одна функция
> Константность локальной копии указателя не влияет на то, какие аргументы нужны вызывающему коду. А вот замена `float*` на `const float*` **меняет тип параметра** (это уже про доступ к самому объекту).

## 8. Ссылки

### 8.1. Другое имя того же объекта

Ссылка — ещё одно **имя** существующего объекта. Не нужно брать адрес в месте вызова и разыменовывать внутри функции.

```cpp
float value = 1.0f;
float& reference = value;       // float& — «ссылка на float»

reference = 5.0f;
std::cout << value << '\n';     // 5  — изменили исходный объект
```

В отличие от копии:

```cpp
float copy = value;             // самостоятельное значение
float& reference = value;       // доступ к value

copy = 7.0f;       // value не изменился
reference = 9.0f;  // value стал 9
```

> [!important] `&` в двух разных ролях
> В **объявлении** (`float& r`) `&` — часть **типа**. В **выражении** (`&value`) — операция **взятия адреса**. Ссылку инициализируют самим именем (`value`), а не адресом.

### 8.2. Инициализация и постоянная привязка

- Ссылку нужно **сразу с чем-то связать**: `float& bad;` — CE. «Пустой» ссылки (в отличие от `nullptr` у указателя) в такой форме нет.
- После инициализации ссылку **нельзя перепривязать** к другому объекту.

```cpp
float z = 1.0f, v = 2.0f;
float& reference = z;

reference = v;                          // НЕ перепривязка! присваивает значение v объекту z
std::cout << z << ' ' << v << '\n';     // 2 2

reference = 8.0f;
std::cout << z << ' ' << v << '\n';     // 8 2
```

> [!tip] Инициализация ≠ присваивание
> При объявлении ссылки мы **устанавливаем связь**; потом `reference = v;` присваивает значение **уже связанному объекту**. Один и тот же знак `=` в двух разных конструкциях. Также: на момент использования ссылки её объект должен ещё **существовать**.

### 8.3. `Swap` с параметрами-ссылками

```cpp
void Swap(float& lhs, float& rhs) {
    float tmp = lhs;
    lhs = rhs;
    rhs = tmp;
	}

float z = 1.0f, v = 2.0f;
Swap(z, v);
std::cout << z << ' ' << v << '\n';     // 2 1
```

Тело **по записи совпадает с `DummySwap`**, но `lhs` и `rhs` теперь — **другие имена** `z` и `v`, а не копии. Адресов не берём, разыменований нет.

> [!important] Тип параметра определяет, работает функция с копией или с оригиналом
> Чтобы понять, может ли функция изменить переменную, **одной строки вызова недостаточно** — нужно смотреть на объявление функции.

Изменяемая ссылка привязывается только к изменяемому объекту: `Swap(z, v)` допустим, `Swap(1.0f, 2.0f)` — нет (литералы — не изменяемые переменные).

## 9. Константные ссылки

### 9.1. Запрет изменения через ссылку

```cpp
float z = 1.0f;
const float& rf = z;

std::cout << rf << '\n';    // 1
// rf = 7.0f;               // CE

z += 1.0f;
std::cout << rf << '\n';    // 2  — rf видит новое значение того же объекта
```

> [!important] Константная ссылка не «замораживает» объект
> Она запрещает менять объект **через эту ссылку**. Если есть другой допустимый способ изменить объект (здесь — имя `z`), значение, видимое через ссылку, тоже изменится.

Обратное запрещено:

```cpp
const int value = 10;
const int& good = value;    // OK
int& bad = value;           // CE: иначе можно было бы изменить const-объект
```

А привязать `const int&` к обычному `int` можно — мы лишь **ограничиваем** действия через новое имя.

### 9.2. Параметр `const int&`

Ссылочный параметр даёт доступ к исходному объекту; случайное присваивание в теле могло бы изменить аргумент вызова. С `const T&` такое не скомпилируется. Кроме того, это **экономит копирование** тяжёлых объектов:

```cpp
void PrintX(const int& x) {
    std::cout << "x=" << x << '\n';
}

int x = 0;
PrintX(x);       // x=0
```

Имя параметра можно поменять (`const int& value`) — смысл тот же; совпадение имени с внешним `x` ничего не значит.

> [!tip] Практическое правило
> Передавай **по ссылке** (обычно по `const&`) любой объект размером больше **двух машинных слов** (≈ 16 байт). Но «всегда передаём по `const&`» — **неверно**: для `int` и других маленьких типов проще и быстрее передавать по значению (здесь `int` взят лишь для разбора механизма).

### 9.3. Почему `PrintX(10)` допустим

```cpp
PrintX(10);     // x=10
```

Для `int&` литерал не подошёл бы. Но `const int&` умеет связываться с **временным объектом**: он существует, пока функция читает значение, и уничтожается после всего выражения вызова.

Первое знакомство с категориями выражений (подробно — [[C++ - Лекция 3 - Выражения, указатели, динамическая память|в лекции 3]]):
- `x` — имя переменной, обозначает существующий объект → **lvalue**
- `10` — литерал → **prvalue**

Обычная `int&` к prvalue не привязывается, `const int&` — привязывается.

## 10. Как передать массив

Одного указателя на первый элемент **недостаточно** — он не говорит, сколько элементов можно просматривать.

**Вариант 1: начало + размер**

```cpp
void PrintArray(const int* data, int size);

int values[] = {3, 1, 4};
PrintArray(values, 3);       // имя массива → указатель на первый элемент
```

`const int*`, потому что для вывода менять элементы не нужно. Размер должен соответствовать реальной доступной части.

**Вариант 2: начало + конец (полуинтервал `[begin, end)`)**

```cpp
void PrintRange(const int* begin, const int* end);

PrintRange(values, values + 3);   // values + 3 — позиция СРАЗУ ПОСЛЕ последнего элемента
```

`values + 3` допустимо **как граница**, но разыменовывать его **нельзя**. Так же устроены стандартные алгоритмы: `std::sort(values, values + 3)` (`<algorithm>`).

> [!tip] Пустой диапазон
> Если `begin == end`, диапазон пустой. Поэтому в цикле проверяем, что указатель ещё не достиг конца, и **только потом** читаем элемент. Вот почему конечный указатель удобно ставить **за последним элементом**.

## 11. Вопросы на подумать (с ответами)

### 11.1. Копия, указатель или ссылка?

```cpp
int a = 1;
int b = a;
int* p = &a;
int& r = a;

b = 2;
*p = 3;
r = 4;
std::cout << a << ' ' << b << '\n';
```

> [!success]- Ответ
> Выведется **`4 2`**.
> - `b = 2;` — меняет **только копию** `b` (`a` не трогает)
> - `*p = 3;` — меняет `a` через указатель (`a == 3`)
> - `r = 4;` — меняет `a` через ссылку (`a == 4`)

### 11.2. Можно ли перепривязать ссылку?

```cpp
int a = 10;
int b = 20;
int& r = a;
int* p = &a;

r = b;
p = &b;
r = 30;
std::cout << a << ' ' << b << '\n';
```

> [!success]- Ответ
> Выведется **`30 20`**.
> - `r = b;` — **не перепривязка**, а присваивание: `a` становится `20`
> - `p = &b;` — указатель `p` теперь указывает на `b` (можно перенаправлять)
> - `r = 30;` — `r` по-прежнему привязана к `a`, поэтому `a == 30`, а `b` остался `20`
>
> Последнее присваивание не меняет объект, на который указывает `p` (то есть `b`), потому что ссылка `r` связана с `a` навсегда.

### 11.3. Что именно защищает `const`?

```cpp
int x = 1;
const int y = 2;

int& a = x;                // 4
int& b = y;                // 5
const int& c = x;          // 6
const int& d = 10;         // 7
int* const p = &x;         // 8
const int* q = &x;         // 9

c = 3;                     // 11
x = 3;                     // 12
*p = 4;                    // 13
p = nullptr;               // 14
q = &y;                    // 15
*q = 4;                    // 16
```

(строки рассматриваются независимо друг от друга)

> [!success]- Ответ
> **Допустимы:** 4, 6, 7, 8, 9, 12, 13, 15.
>
> | Строка | Почему |
> |---|---|
> | 5 `int& b = y;` | **CE**: `y` — `const int`, через `int&` можно было бы менять константный объект |
> | 7 `const int& d = 10;` | OK: константная ссылка может связаться с временным объектом |
> | 11 `c = 3;` | **CE**: через `const int&` присваивать нельзя |
> | 14 `p = nullptr;` | **CE**: `p` — константный указатель (`int* const`) |
> | 15 `q = &y;` | OK: `q` — указатель на константный `int`, сам `q` не константный, а `y` как раз `const int` |
> | 16 `*q = 4;` | **CE**: объект через `const int*` менять нельзя |

### 11.4. Обмен с самим собой и пустой диапазон

**а)** Что произойдёт при `Swap(z, z)` (версия с `float&`)?

**б)** Напиши тело `PrintRange` и скажи, что она выведет при `PrintRange(values, values)`.

> [!success]- Ответ
> **а)** Обе ссылки (`lhs` и `rhs`) — это **один и тот же объект** `z`. Трассировка: `tmp = lhs` → `tmp = z`; `lhs = rhs` → `z = z` (без изменений); `rhs = tmp` → `z = tmp` (то же старое значение). В итоге `z` **не изменился** — всё корректно.
>
> **б)** Один из вариантов:
> ```cpp
> void PrintRange(const int* begin, const int* end) {
>     for (const int* p = begin; p != end; ++p) {
>         std::cout << *p << ' ';
>     }
> }
> ```
> При `begin == end` условие `p != end` ложно с самого начала — тело цикла **не выполняется ни разу**, функция **ничего не выведет** и не прочитает ни одного элемента.
>
> Вариант с индексом и размером:
> ```cpp
> void PrintArray(const int* data, int size) {
>     for (int i = 0; i < size; ++i) std::cout << data[i] << ' ';
> }
> ```

## Итог лекции

- Функция = имя + параметры + тело + возвращаемое значение; **аргументы** — в вызове, **параметры** — в заголовке
- **Объявление** (без тела) позволяет вызывать функцию раньше определения; определение — **одно** (ODR); в сигнатуру входят имя и типы параметров, но не возвращаемый тип, не имена и не аргументы по умолчанию
- Аргументы по умолчанию задаются **в объявлении** и опускаются только с конца
- Если на каком-то пути нет `return` — UB (кроме `main`)
- **По значению** — копия; изменить переменные вызывающей функции можно через **указатель** (адрес тоже копируется, но ведёт к тому же объекту) или **ссылку** (другое имя того же объекта)
- Ссылка инициализируется сразу и **не перепривязывается**; `reference = v;` — присваивание объекту
- `const T&` — безопасный и дешёвый способ передать большой объект «только для чтения»; может связываться с временными объектами
- Массив в функцию: указатель + размер, либо пара указателей `[begin, end)`
