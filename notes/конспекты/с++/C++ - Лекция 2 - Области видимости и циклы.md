# Часть 1. Область действия и область видимости

## 1. Зачем это обсуждать

У переменной, кроме типа и значения, есть ещё два свойства:

- **где переменная существует**
- **где к ней можно обратиться по имени**

На маленьких программах это кажется очевидным, но когда появляются вложенные блоки, одинаковые имена и глобальные переменные, без этих правил код превращается в «угадайку».

---

## 2. Составной оператор (блок)

**Блок** — последовательность операторов в фигурных скобках `{ ... }`. Сам блок — тоже **оператор**, поэтому его можно ставить везде, где синтаксис ждёт один оператор (после `if`, `while`, `for`).

```cpp
int main() {
    int x = 1;

    {                                   // начало первого блока
        int y = 2;
        std::cout << x + 3 * y << '\n';

        {                               // начало второго блока
            return 0;
        }                               // конец второго блока
    }                                   // конец первого блока

    {}                                  // пустой блок
}
```

Блоки можно вкладывать друг в друга, и в них может быть любое число операторов, включая ноль.

### Блок ограничивает время жизни переменных

```cpp
int main() {
    int x = 1;
    {
        int y = 2;
        std::cout << x + 3 * y << '\n';
    }               // здесь y уже уничтожена
    return y;       // ошибка: имени y здесь нет
}
```

Компилятор скажет: `error: 'y' was not declared in this scope`.

---

## 3. Автоматическая область действия

Обычная локальная переменная действует **от места объявления до конца ближайшего блока**, в котором она объявлена. Такие переменные называются **автоматическими**.

```cpp
int main() {
    int x;
    {
        float y;
        {
            bool b;
            {
                char c;
            }   // здесь заканчивается действие c
        }       // здесь заканчивается действие b
    }           // здесь заканчивается действие y
}               // здесь заканчивается действие x
```

> [!tip] Почему «автоматическая»
> Программист не пишет отдельную команду освобождения памяти: объект появляется при входе в нужную часть программы и исчезает при выходе из неё. (Для сравнения: динамическая память из `new` так не работает — её нужно освобождать вручную, см. [[C++ - Лекция 3 - Выражения, указатели, динамическая память|лекцию 3]].)

---

## 4. Глобальная область действия

Переменные, объявленные **вне функций**, — **глобальные**. Они существуют всё время работы программы.

```cpp
int x = 1;

int main() {
    int y = 2;
    std::cout << x + 3 * y << '\n';
    return 0;
}
```

> [!important] Но «существует» ≠ «можно использовать откуда угодно»
> В C++ **имя должно быть объявлено до использования**. Вот так не сработает:
> ```cpp
> int main() {
>     int y = 2;
>     std::cout << x + 3 * y << '\n';   // ошибка: компилятор ещё не знает x
>     return 0;
> }
>
> int x = 1;    // глобальная, но объявлена слишком поздно
> ```

---

## 5. Объявление и определение (`extern`)

Чтобы пример выше заработал, имя `x` можно **объявить заранее**, а **определить** позже. Для этого служит `extern`:

```cpp
int main() {
    int y = 2;
    extern int x;                  // объявление без определения
    std::cout << x + 3 * y << '\n';
    return 0;
}

int x = 1;                         // определение x
```

- **Объявление** сообщает компилятору, что такое имя существует
- **Определение** действительно **создаёт объект**

> [!tip] На практике
> В учебном коде проще писать глобальные переменные до функций. Но различие «объявление vs определение» ещё много раз встретится: в функциях, заголовочных файлах и раздельной компиляции (см. [[C++ - Лекция 6 - Перегрузка, static, шаблоны, приведения типов|лекцию 6]]).

## 6. Область видимости (scope)

Будет ли ошибка здесь?

```cpp
int x = 0;

int main() {
    int x = 1;
    std::cout << x << '\n';
    return 0;
}
```

**Ошибки нет**, выведется `1`.

**Область видимости (scope)** — часть кода, из которой возможен обычный доступ к переменной по имени.

- Область видимости **не может быть больше** области действия (нельзя увидеть по имени уже уничтоженный объект)
- Но она **может быть меньше**: глобальный `x` продолжает существовать во время `main`, но локальный `x` **скрывает** его имя

### Разница между понятиями

| | Отвечает на вопрос |
|---|---|
| **Область действия** (lifetime) | где объект **существует**? |
| **Область видимости** (scope) | где **имя** обозначает именно этот объект? |

Иногда они почти совпадают, а иногда объект живёт, но его имя временно скрыто (как глобальный `x` выше).

---

## 7. Оператор разрешения области видимости `::`

Чтобы обратиться именно к **глобальной** переменной, ставим `::` перед именем:

```cpp
int x = 0;

int main() {
    int x = 1;
    std::cout << x << '\n';     // 1  (локальная)
    std::cout << ::x << '\n';   // 0  (глобальная)
    return 0;
}
```

### Вложенные области

Поиск имени идёт **от самой вложенной области наружу**:

```cpp
int x = 0;

int main() {
    int x = 1;
    {
        int x = 2;
        std::cout << x << '\n';     // 2  (самый внутренний)
        std::cout << ::x << '\n';   // 0  (глобальный)
    }
    return 0;
}
```

> [!warning] К «промежуточному» `x = 1` обратиться по имени уже нельзя
> Внутренний `x` его скрывает, а `::x` ведёт сразу в **глобальную** область, минуя промежуточные. Поэтому не заводи лишних переменных с одинаковыми именами в вложенных блоках — это путаница.

---

## 8. Зачем нужны блоки

Не только ради синтаксиса `if`/циклов: блоки **ограничивают область действия** временных переменных.

```cpp
int main() {
    int answer = 0;
    {
        int temporary = 40 + 2;
        answer = temporary;
    }
    std::cout << answer << '\n';    // temporary здесь уже не существует
}
```

Чем меньше участок программы, где переменная видна, тем проще понять, где её могли изменить.

### Итоги части 1

- Блок — последовательность операторов в `{}`
- Локальная автоматическая переменная действует от объявления до конца ближайшего блока
- Глобальная существует всё время работы программы
- Имя нужно объявить до использования; `extern` объявляет без определения
- **Область действия** — где объект существует; **область видимости** — где имя ведёт на этот объект
- Внутреннее имя скрывает внешнее; `::x` — обращение к глобальному `x`

# Часть 2. Циклы

## 9. Проблема

- **Задача 1:** ввести 3 числа и найти сумму — просто (`cin >> x >> y >> z`)
- **Задача 2:** ввести 10 чисел — уже приходится копировать строки `std::cin >> x; sum += x;` десять раз
- **Задача 3:** ввести `n`, а затем `n` чисел — **`n` неизвестно на этапе компиляции**, вручную не расписать

Нужно **повторять** действие нужное число раз — для этого и есть циклы.

---

## 10. Цикл `while`

```cpp
while (<condition>) <statement>
```

- `condition` — выражение (или объявление переменной с инициализатором), приводимое к `bool`
- `statement` — оператор (обычно составной, то есть блок)

**Решение задачи 3:**

```cpp
int n;
std::cin >> n;

int sum = 0;
while (n > 0) {
    int x;
    std::cin >> x;
    sum += x;
    --n;
}
std::cout << sum << '\n';
```

### Примеры экзотических `while`

```cpp
while (true) std::cout << 0;          // бесконечный цикл

x = -5;
while (int sqr = x * x) {             // переменная объявляется прямо в условии
    ++x;
    std::cout << sqr << '\n';
}                                     // выведет 25 16 9 4 1, потом x == 0, sqr == 0 → стоп

while (x);                            // пустой цикл
```

> [!warning] Последний цикл — UB
> `while (x);` — **неопределённое поведение**, если `x` не меняется и у цикла нет побочных действий (бесконечный цикл без наблюдаемых эффектов компилятору разрешено «выкинуть» или сломать).

---

## 11. Цикл `do-while`

```cpp
do <statement> while (<condition>);
```

Отличие от `while`: тело выполняется **до** проверки условия, поэтому **хотя бы одна итерация гарантирована**.

```cpp
int x = 0;
int sum = 0;

do {
    std::cin >> x;
    sum += x;
} while (x != 0);       // читаем числа до первого нуля

std::cout << sum << '\n';
```

Здесь `do-while` естественнее: до первого чтения проверять условие «не ноль ли `x`» просто нечем.

> [!tip] Как выбрать цикл
> Спроси себя: логика задачи построена вокруг **условия входа** (проверяем до тела — `while`/`for`, тело может не выполниться ни разу) или **условия выхода** (проверяем после тела — `do-while`, минимум одна итерация)?

---

## 12. Цикл `for`

Решение задачи через `while` с отдельным счётчиком:

```cpp
int i = 0;
while (i < n) {
    int x; std::cin >> x; sum += x;
    ++i;
}
```

**Что тут не нравится:** счётчик `i` объявлен и виден **вне цикла**; неочевидно, сколько будет итераций; легко забыть `++i` или не найти его глазами.

**`for` собирает всё в одной строке:**

```cpp
for ([init]; [condition]; [expression]) <statement>
```

- `init` — выражение или объявление; объявленная переменная живёт **только внутри цикла**
- `condition` — условие продолжения (приводимо к `bool`; если пусто — всегда истина)
- `expression` — выражение в **конце каждой итерации**
- `statement` — тело

```cpp
for (int i = 0; i < n; ++i) ...
```

**`for` эквивалентен такому `while`:**

```cpp
{
    [init];
    while ([condition]) {        // while (true), если condition пуст
        <statement>
        [expression];
    }
}
```

(обрати внимание на внешние `{}` — именно они ограничивают область видимости переменной из `init`).

### Примеры `for`

```cpp
for (int i = 0; i < n; ++i) std::cout << i << '\n';

for (int i = 0; i < n; i += 2) {              // шаг 2
    std::cout << i << '\n';
}

for (std::cin >> x; x != 0; std::cin >> x) {  // чтение до нуля
    std::cout << x * x << '\n';
}

for (;;) ...                                   // бесконечный цикл
for (; x;) ...                                 // аналог while (x)

for (int i = 0, j = 0; i < n && j < m; ++i, ++j) ...   // две переменные (запятая)
```

## 13. Управляющие операторы

### `break` — досрочный выход из цикла

```cpp
for (int i = 0; i < n; ++i) {
    int x;
    std::cin >> x;
    if (x == 0) {
        std::cout << "Division by zero\n";
        break;                        // выходим из цикла целиком
    }
    std::cout << y / x << '\n';
}
```

### `continue` — досрочное завершение **текущей итерации**

```cpp
for (int i = 0; i < n; ++i) {
    int x;
    std::cin >> x;
    if (x == 0) {
        std::cout << "Division by zero\n";
        continue;                     // пропускаем деление, идём к следующей итерации
    }
    std::cout << y / x << '\n';
}
```

> [!tip] `break` vs `continue`
> `break` **прекращает** цикл вообще, `continue` лишь **пропускает остаток** текущего шага и переходит к следующему (в `for` — выполнив `expression`).

## 14. Оператор `goto` (в курсе запрещён)

`goto` делает безусловный «прыжок» к **метке** внутри функции, независимо от условий.

```cpp
int main() {
    int x;
    std::cin >> x;
    goto label;

    int y;
    std::cin >> y;
    std::cout << x + y << '\n';

    label:
    return 0;
}
```

Цикл можно выразить через `goto` (на этом же основан и `switch`):

```cpp
for (int i = 0; i < n; ++i) ...
// <=>
    int i = 0;
loop:
    if (i < n) {
        ...
        ++i;
        goto loop;
    }
```

**Почему плохо:** визуальный порядок строк перестаёт отражать порядок выполнения; читателю приходится восстанавливать граф переходов; легко пропустить инициализацию; усложняется отладка.

### Два примера из лекции

```cpp
int x = 0;
label:
    int y = 1;
    ...
    goto label;          // назад: y просто проинициализируется заново — корректно
```

```cpp
goto label;
    int x = 0;
    int y = 1;
label:
    std::cout << x * y << '\n';   // перепрыгнули инициализацию!
```

> [!warning] Уточнение к методичке
> В методичке второй пример назван UB («использование переменных без инициализации»). Но в C++ такой код **ещё строже**: переход мимо объявления с инициализацией **запрещён стандартом**, и обычные компиляторы (GCC, Clang) выдают **ошибку компиляции** (`jump to label crosses initialization`), а не пропускают его до запуска.

**Чем заменять `goto`:** циклы, `break`, `continue`, ранний `return`, флаг состояния или отдельная функция.

> «...the quality of programmers is a decreasing function of the density of goto statements in the programs they produce.»
> — Edsger Dijkstra, *Go To Statement Considered Harmful*, 1968

## Итог лекции

- Блок `{}` ограничивает **область действия** переменных; **область видимости** может быть уже области действия (внутреннее имя скрывает внешнее)
- `::x` — глобальное имя, `extern` — объявление без определения
- `while` — условие входа; `do-while` — минимум одна итерация; `for` — компактная форма `while` с локальным счётчиком
- `break` выходит из цикла, `continue` пропускает остаток итерации
- `goto` не используем: он ломает читаемость, а переход мимо инициализации вообще запрещён
