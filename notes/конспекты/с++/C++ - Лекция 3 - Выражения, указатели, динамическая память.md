## 1. Выражения (Expressions)

**Выражение** — последовательность операций и их операндов, задающая вычисление. Результат выражения проявляется в двух вещах:

1. **возвращаемое значение**
2. **побочные эффекты** (например, изменение переменной)

```
2 + 2        x * y        x + 3 * y        x = y        y *= 10 % x
```

### 1.1. Присваивающие операции

Обычное присваивание `=` и составные (присваивающие арифметические) операции:

```cpp
x += 5;    // x = x + 5
y %= 2;    // y = y % 2
y |= 9;    // y = y | 9
```

> [!warning] ⚠️ Опечатка в методичке
> В комментарии к `y |= 9` в оригинале написано `z = z | 9`. Правильно: `y = y | 9`.

Присваивающие операции не только меняют переменную, но и **возвращают результат** — новое значение:

```cpp
std::cout << (y = 5);      // 5
std::cout << (x = y * y);  // 25
std::cout << (x += 5);     // 30
```

Поэтому можно строить цепочки:

```cpp
x = y = 5;
z = x = y *= y;
```

### Результат присваивания — это сама переменная

Присваивание возвращает не просто число, а **саму исходную переменную**. Поэтому в результат можно снова что-то присвоить:

```cpp
(x = y) = 5;    // x == 5
(x = y) *= 0;   // x == 0
```

А вот литералу и результату обычной операции присвоить нельзя:

```cpp
5 = x;        // Ошибка
x * y = 10;   // Ошибка
x + y = 10;   // Ошибка
```

> [!tip] Почему так
> Присваивание изменяет левую переменную и возвращает её же. А выражение `x + y` вычисляет только сумму: **отдельной переменной с этой суммой нигде в памяти нет**, менять там нечего. Присваивать можно только объекту, значение которого можно изменить.

### 1.2. Категории значений: lvalue и prvalue

Каждое выражение характеризуется двумя вещами:
- **тип** возвращаемого значения
- **категория значения** — материален ли результат, то есть существует ли он как объект в памяти

| Категория | Смысл | Примеры |
|---|---|---|
| **lvalue** | материальное значение (есть место в памяти) | `x`, `x = 5`, `x *= 2`, `++x` |
| **prvalue** | нематериальное (просто временное значение) | `x + y`, `5`, `x / 2.`, `x++` |

Примеры разбора:

| Выражение | Тип | Побочный эффект | Категория |
|---|---|---|---|
| `x + y` | `int` | нет | prvalue |
| `x = 5` | `int` | в `x` хранится 5 | lvalue (это `x`) |
| `x *= 2` | `int` | в `x` хранится 10 | lvalue (это `x`) |
| `y + (x *= 6)` | `int` | в `x` хранится 60 | prvalue |
| `x / 2.` | `double` | нет | prvalue |

Теперь ошибки понятны:

```cpp
5 = x;       // Ошибка: lvalue required as left operand of assignment
x * y = 10;  // Ошибка: то же самое
```

> [!important] Запомни
> **lvalue** можно ставить слева от `=`, брать у него адрес `&`, применять к нему `++`/`--`. **prvalue** — нельзя.

## 2. Инкремент и декремент

Унарные операции, увеличивающие/уменьшающие аргумент на 1. Как и присваивание, применимы только к **lvalue**.

```cpp
int x = 0;
x++;   // постфиксный инкремент
++x;   // префиксный инкремент
x--;   // постфиксный декремент
--x;   // префиксный декремент
```

### Префикс vs постфикс

Обе формы одинаково меняют переменную. Отличие — в **возвращаемом значении**:

- **префиксная** (`++x`, `--x`) возвращает **уже обновлённое** значение (саму переменную, это lvalue)
- **постфиксная** (`x++`, `x--`) возвращает **старое** значение (до обновления, это prvalue)

```cpp
int x = 0;
int a = ++x;  // x стало 1, a получило 1
int b = x++;  // b получило 1, затем x стало 2

std::cout << ++x << '\n';  // 3
std::cout << x++ << '\n';  // 3 (а x после этого станет 4)
```

Из-за разницы в категориях:

```cpp
--x = 10;    // OK: --x это lvalue, x == 10
x-- = 11;    // Ошибка компиляции: x-- это prvalue
++5;         // Ошибка: lvalue required
(x + 1)--;   // Ошибка
```

## 3. Операции `sizeof`, `static_cast`, запятая

### 3.1. `sizeof`

Унарная операция, возвращает размер **в байтах**.
- применённая к **типу** — сколько памяти занимает этот тип
- применённая к **выражению** — размер типа результата

> [!important] `sizeof` не вычисляет выражение, а только анализирует его тип
> ```cpp
> long long x;
> sizeof('a');      // 1
> sizeof(1 / 0);    // 4  (деления на ноль не происходит!)
> sizeof(x = 1);    // 8  (x НЕ меняется)
> sizeof(++x);      // 8  (x НЕ меняется)
> ```

### 3.2. `static_cast`

Принудительно выполняет допустимое преобразование типа:

```cpp
static_cast<новый_тип>(выражение)
```

```cpp
int x = 2;
int y = 2'000'000'000;
std::cout << x / y << '\n';                      // 0 (целочисленное деление)
std::cout << static_cast<float>(x) / y << '\n';  // дробный результат

std::cout << x * y << '\n';                      // переполнение (UB)
std::cout << static_cast<int64_t>(x) * y << '\n'; // 4000000000, OK
```

### 3.3. Операция запятая

Объединяет несколько выражений в одно:

```cpp
++x, y--, std::cout << x + y, 5;
```

- гарантирует, что **сначала** вычисляется левое выражение
- результатом всей операции является результат **правого** операнда

## 4. Модель памяти

- Память — **нумерованная последовательность байт**. Номер байта — его **адрес**.
- Области памяти: глобальная (статическая), автоматическая (стековая), динамическая, потоковая (её в курсе не разбираем).

### Операция взятия адреса `&`

```cpp
int x;
std::cout << &x << '\n';  // адрес в 16-ричном виде
```

Применима **только к lvalue**. Это даже можно использовать как критерий "является ли выражение lvalue":

```cpp
&x, &(x = 8), &(++x);    // можно: lvalue
&5, &(x + 8), &(x++);    // нельзя: prvalue
```

Результат — значение особого типа, **указатель на тип объекта**:

```cpp
int x;
const float y = 0;
&x;   // int*
&y;   // const float*
```

## 5. Указатели

**Указатель** — тип данных, хранящий адрес другого объекта в памяти. Если `T` — тип, то `T*` — указатель на `T`. Указатели — целое **семейство** типов:

```cpp
int*            // указатель на int
float*          // указатель на float
const char**    // указатель на указатель на константный char
double***       // указатель на указатель на указатель на double
```

### 5.1. Примеры и разыменование

```cpp
int x = 0;
const float y = 0;

int* px = &x;
int* px2 = &(++x);          // == px

const float* cpy = &y;
const int* cpx = &x;        // можно: на const-указатель можно смотреть на неконстантный объект

int** ppx = &px;

float* py = &y;             // CE: нарушает константность y
```

**Разыменование** `*p` — унарная операция над указателем, возвращает **lvalue** того типа, на который указывает указатель:

```cpp
int x = 1;
float y = 2.5;

int* px = &x;
float* py = &y;

*px = 11;
*py = 3.5;

std::cout << *px << ' ' << *py;  // 11 3.5
std::cout << x << ' ' << y;      // 11 3.5 (оригиналы тоже изменились)
```

> [!warning] ⚠️ Опечатка в методичке
> В оригинальном примере написано `int* py = &y;`, где `y` — `float`. Так не скомпилируется (`float*` нельзя присвоить в `int*`). Правильно: `float* py = &y;`.

### 5.2. Арифметика указателей

Адреса — целые числа, но целочисленная арифметика к ним применима **не вся**:

- **Указатель ± целое число** → указатель, сдвинутый на `n` шагов по `sizeof(T)` байт:
  ```cpp
  int32_t* p = ...;
  p + 5;    // + 20 байт
  p - 4;    // - 16 байт
  p += 10;  p -= 12;  ++p;  p--;
  ```
- **Указатель − указатель** (одинакового типа) → число элементов между ними (разница в байтах / `sizeof(T)`):
  ```cpp
  int x, y, z;
  std::cout << &z - &x << '\n';  // скорее всего 2
  ```
- Все остальные арифметические операции с указателями недопустимы.

> [!warning] Важная оговорка
> Разность указателей на **отдельные переменные** или сдвиг указателя на переменную, с точки зрения стандарта, не даёт разумного результата. Разыменование такого указателя — **UB**. Нормально эта арифметика работает внутри **массивов** (см. [[C++ - Лекция 4 - Массивы|лекцию 4]]).

### 5.3. Указатели и `const`

Есть две независимые "константности":

**1. Указатель на константу** — нельзя менять объект, на который смотрим:
```cpp
const int* px = &x;   // либо int const*
std::cin >> *px;      // CE: объект считается неизменяемым
std::cout << *px;     // OK: читать можно
px = &y;              // OK: сам указатель можно перенаправить
```

**2. Константный указатель** — нельзя менять сам указатель:
```cpp
int* const px = &x;
std::cin >> *px;      // OK: объект менять можно
px = &y;              // CE: указатель неизменяемый
++px;                 // CE
```

**Комбинации:**
```cpp
const int* px;          // указатель на константу
int const* py;          // то же самое
int* const pz;          // константный указатель
const int* const pa;    // константный указатель на константу
int const* const pb;    // то же самое
```

> [!tip] Лайфхак: читай тип указателя справа налево
> `int const* const` → "константный (const) указатель (*) на константный (const) int".

### 5.4. Указатели на указатели

Указатель — это тоже тип, поэтому на него тоже можно сделать указатель (и с `const` это тоже работает):

```cpp
float x;
float* px = &x;
float** ppx = &px;
float*** pppx = &ppx;

const float* const** const p = ...;
// константный указатель на указатель на константный указатель на константу float
```

### 5.5. Нулевой указатель

Чтение неинициализированного указателя — **UB**, как и для любой переменной:

```cpp
int* p;
std::cout << p << ' ' << *p;  // UB
```

Присвоить указателю произвольное число нельзя:
```cpp
int* r = 10;  // CE: из int в int* преобразовывать нельзя
```

Раньше было исключение: указателю можно присвоить `0` (нулевой адрес). По стандарту по нулевому адресу ничего находиться не может, поэтому разыменование такого указателя — тоже UB. Но такое исключение создаёт асимметрию (число 10 нельзя, а 0 почему-то можно).

> [!important] Правильный способ в современном C++ — `nullptr`
> ```cpp
> int* p = nullptr;
> const float* pp = nullptr;
> ```
> `nullptr` — значение специального типа `std::nullptr_t`, которое неявно приводится к нулевому указателю **любого** типа. **Используй только `nullptr`** для обозначения пустого указателя.

### 5.6. Указатель на `void`

`void*` хранит адрес **без учёта типа** того, что там лежит:

```cpp
int x;
void* p = &x;

std::cout << p;   // OK: можно вывести адрес
std::cin >> *p;   // CE: не ясно, что записывать
std::cout << *p;  // CE: не ясно, что читать
```

### 5.7. «Висячий» указатель

```cpp
int main() {
    int* p = nullptr;
    {
        int x = 0;
        p = &x;
    }               // здесь x уничтожен
    return *p;      // UB!
}
```

Область действия объекта закончилась раньше, чем область действия указателя на него. Чтение/запись по такому указателю — **UB**. Не допускай «провисания» указателей!

## 6. Динамическая память

### 6.1. Зачем она нужна

Глобальные и стековые переменные имеют ограничения:
- **строго фиксированное время жизни**: глобальные живут до конца программы, локальные — до конца блока
- обычно ограничены несколькими **мегабайтами**, а реальным программам часто нужно гораздо больше

### 6.2. Выражение `new`

`new T` / `new T(...)` / `new T[...]` создаёт объект типа `T` в **динамической области** и возвращает указатель на него:

```cpp
int* pa = new int;       // без инициализации
int* pb = new int(11);   // инициализация числом 11
int* pc = new int[13];   // массив из 13 int
```

> [!warning] ⚠️ Опечатка в методичке
> В оригинале у `new int[13]` комментарий "инициализация числом 13". Это **неверно**: `new int[13]` создаёт **массив из 13 элементов** (неинициализированных), а не одно число 13. Для одного числа 13 нужно `new int(13)`.

Объекты в динамической области живут **с момента вызова `new` до конца программы** (или до явного `delete`). Поэтому можно создавать объекты внутри блока, которые переживут этот блок:

```cpp
int* p = nullptr;
{
    int x = 11;
    p = new int(13);
}
std::cout << x;   // CE: x уже уничтожен
std::cout << *p;  // OK
```

Но так память постепенно «засоряется», поэтому её нужно освобождать.

### 6.3. Выражение `delete`

```cpp
int* p = new int;
// ...
delete p;   // удаляет объект, возвращает память системе
```

- удалять можно **только** то, что выделено через `new`; в остальных случаях `delete` — UB
- `delete` для **нулевого указателя** — корректная операция (ничего не делает)

### 6.4. Утечка памяти

**Утечка памяти** — неконтролируемый рост лишней занятой памяти из-за неосвобождённых объектов:

```cpp
int* p = new int;
p = nullptr;        // потеряли единственный указатель на память — утечка
new float;          // выделили, но указатель не сохранили — утечка
p = new int;        // и снова не удалили после использования — утечка
```

### 6.5. Другие способы выделения памяти

В языке C основной способ — `malloc`:
- возвращает `void*`
- требует явного количества **байт**
- **не инициализирует** память

```cpp
void* v = std::malloc(11);
int* p = static_cast<int*>(std::malloc(sizeof(int)));
*p = 0;

std::free(v);
std::free(p);
```

В C++ аналог — функции `operator new` / `operator delete` (используются крайне редко). Факт: `new` и `delete` внутри как раз вызывают эти функции.

### 6.6. Две типичные ошибки при работе с `new`

| Ошибка | Как избежать |
|---|---|
| **#1. Use after free** — обратились к объекту после `delete` | не обращаться после `delete` |
| **#2. Memory leak** — не вызвали `delete` | использовать **ownership** и **RAII** (resource acquisition is initialization) |

## 7. Кто должен освобождать память?

Разберём способы передать объект в функцию.

**1) Указатель на динамический объект — владение у вызывающего:**
```cpp
void DoOtherThing() {
    auto n = new Node{};
    n->value = 1;
    DoSomething(n);
    delete n;               // освобождает вызывающая функция
}
void DoSomething(Node* node) { std::cout << node->value << std::endl; }
```

**2) То же, но владение передано вызываемому:**
```cpp
void DoSomething(Node* node) {
    std::cout << node->value << std::endl;
    delete node;            // освобождает вызываемая функция
}
```
> [!warning]
> Нельзя оставлять оба `delete` сразу — объект будет удалён дважды (UB).

**3) Копирование динамического объекта** — у каждого своя копия, каждый удаляет свою:
```cpp
DoSomething(new Node{*n});  // функция получает копию и сама её удалит
delete n;                   // оригинал удаляет вызывающий
```

**4) Указатель на обычный объект (без `new`)** — `delete` вызывать **нельзя**, объект сам уничтожится при выходе из области видимости:
```cpp
Node n;
n.value = 1;
DoSomething(&n);
```

**5) Передача по значению** — функция получает копию, она уничтожается автоматически:
```cpp
void DoSomething(Node node) { ... }
```

**6) Передача с перемещением (`std::move`)** — содержимое перемещается вместо копирования, ничего вручную освобождать не надо:
```cpp
DoSomething(std::move(n));
```

> [!important] Правила владения (ответ на вопрос "кто освобождает?")
> - **Кто выделил — тот и освобождает**,
> - если не передал владение другому,
> - а если другой сделал себе копию — он освобождает свою копию сам.

## Итог лекции

- Выражение даёт **значение** и/или **побочный эффект**; у него есть тип и **категория** (lvalue — материально, prvalue — нет)
- `=`, `+=` и `++x` возвращают lvalue (саму переменную), а `x++` — старое значение (prvalue)
- `sizeof` **не вычисляет** выражение, только смотрит на его тип
- `&x` — адрес (только для lvalue), `*p` — разыменование; `T*` — целое семейство типов
- Арифметика указателей: `p ± n` (шаги по `sizeof(T)`), `p - q` (число элементов); осмысленна в основном внутри массивов
- `const` у указателей читаем **справа налево**: `int const* const`
- Нулевой указатель — только `nullptr`; висячие, неинициализированные указатели — UB
- `new` выделяет в динамической области, `delete` освобождает; ошибки: **use after free** и **утечка памяти**
- Правило владения: кто выделил — тот и освобождает (пока не передал владение)
