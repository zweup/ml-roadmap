## 1. Что можно вернуть по ссылке или указателю

```cpp
int& F() {
    int x = 0;
    return x;        // ОШИБКА: ссылка на локальную переменную
}
```

`x` — автоматическая переменная, она **умирает при выходе из функции** ([[C++ - Лекция 2 - Области видимости и циклы|лекция 2]]). Вернуть ссылку на неё — значит вернуть «висячую» ссылку (UB при использовании), как «висячий указатель» из [[C++ - Лекция 3 - Выражения, указатели, динамическая память|лекции 3]].

**На что можно вернуть ссылку/указатель** (комментарий из кода):
1. на объект в **динамической памяти**
2. на **глобальную** переменную (любой объект со статической областью действия)
3. на переменную, **переданную в функцию по ссылке**

## 2. Статические переменные (`static`)

```cpp
int& G() {
    static int x;     // = 0
    return ++x;
}
```

Свойства **статических переменных**:
- имеют **статическую область действия** (*static storage duration*) — живут всю программу
- **инициализируются один раз** (при первом проходе через объявление)
- **сохраняют значение между вызовами**
- по умолчанию **инициализируются нулями**

Так как `x` живёт всю программу, на неё можно безопасно вернуть ссылку (пункт 2 из раздела 1).

```cpp
std::cout << G() << '\n';   // 1
std::cout << G() << '\n';   // 2
std::cout << G() << '\n';   // 3
G() = 10;                   // G() вернула ссылку на x (x стал 4), присвоили 10
std::cout << G() << '\n';   // 11  (++x от 10)
```

> [!tip] Почему можно писать `G() = 10;`
> `G()` возвращает **ссылку** (`int&`) — это lvalue, ему можно присваивать (см. категории выражений в [[C++ - Лекция 3 - Выражения, указатели, динамическая память|лекции 3]]). Побочный эффект самого вызова (`++x`) тоже происходит.

### Статическая переменная внутри блока

```cpp
void H(int x) {
    std::cout << ++x << ' ';
    {
        static int y;          // одна на всю программу, а не на каждый вызов
        int z = x;             // обычная локальная: создаётся заново при каждом вызове
        std::cout << ++y << ' ' << ++z << '\n';
    }
}

H(1);   // 2 1 3
H(2);   // 3 2 4
H(3);   // 4 3 5
```

Разбор: `x` и `z` создаются заново каждый вызов, поэтому `++x` и `++z` дают одно и то же при тех же аргументах; а `y` **накапливается** (1, 2, 3).

## 3. Перегрузка функций

Функции с **одним именем** можно перегружать **по количеству и типам аргументов**:

```cpp
void Swap(int& lhs, int& rhs)     { ... }
void Swap(float& lhs, float& rhs) { ... }
void Swap(float& x)               { }        // другая арность

void PrintValue(double x)         { ... }
void PrintValue(int x)            { ... }
void PrintValue(long x)           { ... }
void PrintValue(long x, long y)   { ... }
```

### Как выбирается перегрузка

При вызове выбирается **наиболее подходящая** версия — требующая **наименьшего числа преобразований**. Порядок предпочтения: точное совпадение → **расширение (promotion)** → **преобразование (conversion)**.

```cpp
float y = 0;
PrintValue(y);        // double: float → double — расширение (promotion)
PrintValue(x);        // x — int: точное совпадение с PrintValue(int)
PrintValue(y, y);     // единственная двухаргументная: PrintValue(long, long)
```

> [!tip] Зачем в коде пометка «не понятно, какую перегрузку выбрать, если бы не было версии с double»
> Без `PrintValue(double)` аргумент `float` пришлось бы **преобразовывать** в `int` или в `long` — оба варианта равноправны, и компилятор выдаст ошибку неоднозначности. Версия `double` спасает: `float → double` — **расширение**, оно «лучше» любого преобразования.

> [!warning] ⚠️ Неточность в комментарии
> В коде написано, что расширением является «`int -> long`, `float -> double`». Строго по стандарту **расширение** — это `char`/`short`/`bool` → `int` и `float` → `double`; а `int → long` — это уже **преобразование**. На выбор перегрузки в примере это не влияет, но не заучивай `int → long` как promotion. Верно и то, что `float → long double` и `double → long double` — преобразования.

### Константность параметра при выборе перегрузки

- **Константность самого параметра игнорируется**: `void f(int)` и `void f(const int)` — **одна и та же** функция
- `int* const` — константность на **самом параметре** (указателе) → **игнорируется**
- `const int*` — константность на **объекте, на который указываем** → **НЕ игнорируется** (это другой тип параметра)

(см. разницу `const int*` / `int* const` в [[C++ - Лекция 3 - Выражения, указатели, динамическая память|лекции 3]] и [[C++ - Лекция 5 - Функции и ссылки|лекции 5]])

## 4. Шаблоны функций

Чтобы не писать `Swap` для каждого типа, делаем **шаблон**:

```cpp
template <typename T>
void Swap(T& lhs, T& rhs) {
    T tmp = lhs;
    lhs = rhs;
    rhs = tmp;
}

template <typename T, typename U>
void PrintValues(T x, U y) {
    std::cout << "x=" << x << ' ' << "y=" << y << '\n';
}
```

Компилятор сам **создаёт версию функции** под нужные типы (*инстанцирует* шаблон). Тип `T` можно либо **вывести** из аргументов, либо указать явно:

```cpp
double lhs = 2, rhs = 1;
Swap(lhs, rhs);                 // T = double (выведено)

int& rx = x;
PrintValues(rx, 0.0);           // T = int, U = double   → "x=0 y=0"
PrintValues<float>(1, 0.0);     // T = float (явно), U = double (выведено) → "x=1 y=0"
```

**Типы выводятся для каждого аргумента независимо.**

> [!tip] Если подходят и обычная функция, и шаблон
> Для `float` вызов `Swap(z, v)` выберет **обычную** `Swap(float&, float&)`, а для `double` обычной версии нет — сработает шаблон. (Дополнение: при прочих равных предпочитается нешаблонная функция.)

> [!warning] ⚠️ Неточность в комментарии
> В коде написано: «шаблоны на этапе **препроцессинга** превращаются в перегрузки». На самом деле шаблоны обрабатывает **компилятор** (при инстанцировании), а не препроцессор — препроцессор занимается лишь `#include`/`#define` (см. [[C++ - Лекция 1 - Устройство программы, типы, память, условное выполнение|лекцию 1]]). Идея «шаблон порождает набор перегрузок» верна.

## 5. Выведение типа шаблона

Из трёх комментариев в `main(3).cpp` — три функции-пробника:

```cpp
template <typename T> void F(T x)        { ... }   // по значению
template <typename T> void G(T& x)       { ... }   // по ссылке
template <typename T> void H(const T& x) { ... }   // по константной ссылке
```

### 5.1. Выведение по значению (`T x`)

1. **отбрасываются `const` и `volatile`** верхнего уровня
2. **ссылочность** аргумента теряется
3. **массив** → указатель на первый элемент
4. **функция** → указатель на функцию

> [!tip] Что такое `volatile` (в коде стоит «что это?»)
> Дополнение: `volatile` — квалификатор типа, сообщающий компилятору, что значение переменной **может измениться «незаметно» для программы** (например, аппаратным регистром). Компилятор не имеет права оптимизировать обращения к такой переменной. Работает как `const`: тоже может быть у типа и отбрасывается при выведении по значению.

### 5.2. Выведение по ссылке (`T& x`)

1. **сохраняются `const` и `volatile`** (тип `T` «впитывает» их)
2. ссылочность аргумента теряется (`T` — без `&`, ссылкой делает сам `T&`)
3. **функция остаётся функцией**, никуда не низводится
4. **rvalue нельзя** передать по lvalue-ссылке

> [!warning] ⚠️ Пункт про массив в комментарии неверен
> В комментарии для ссылки написано, что «массив низводится до указателя». Это **неправильно** и противоречит самому примеру из кода: для ссылочного параметра массив **не** низводится — выводится `T = int[10]`. Низведение до указателя — особенность **выведения по значению**.

### 5.3. Выведение по константной ссылке (`const T& x`)

То же, что для `T&`, но с одним отличием: **rvalue принять можно** (константная lvalue-ссылка связывается с временными объектами, см. [[C++ - Лекция 5 - Функции и ссылки|лекцию 5]]).

### 5.4. Таблица выведения из кода (функция `H(const T&)`)

```cpp
int x = 1;
const int cx = 10;
int& rx = x;
int arr[kConst]{};          // int[10]

H(x);       // T = int
H(cx);      // T = int      (const «впитал» параметр const T&)
H(rx);      // T = int      (ссылочность теряется)
H(arr);     // T = int[10]  (массив НЕ низводится)
H(10);      // T = int      (rvalue принят по const&)
H(Square);  // T = int(int) (функция остаётся функцией; в комментарии записано «int ()(int)»)
```

## 6. Приведения типов

```cpp
int x = 1;
double y = (double)x;                       // приведение в стиле C
double z = static_cast<double>(x);          // C++-стиль
```

| Приведение | Что делает |
|---|---|
| `(T)x` | приведение в **стиле C**: «делает что угодно», трудно искать глазами и легко ошибиться — в C++ лучше не использовать |
| `static_cast<T>(x)` | выполняет **допустимые преобразования** с точки зрения примитивных типов (как в [[C++ - Лекция 3 - Выражения, указатели, динамическая память\|лекции 3]]) |
| `const_cast<T>(x)` | меняет **константность** |
| `dynamic_cast<T>(x)` | пока не разбираем |
| `reinterpret_cast<T>(x)` | переинтерпретация битов (в коде закомментирован) |

Пример `const_cast`:

```cpp
double z = ...;
double& rz = z;
const double& crz = const_cast<const double&>(rz);   // добавили const
double& rzz = const_cast<double&>(crz);              // убрали const
```

И пример `reinterpret_cast` (закомментирован в коде):

```cpp
// uint64_t& v = reinterpret_cast<uint64_t&>(z);     // смотрим на биты double как на uint64_t
```

> [!warning] Дополнение: осторожно с `const_cast`
> Убирать `const` через `const_cast` безопасно только если исходный объект **изначально не был** константным. Если менять через такую ссылку объект, объявленный как `const`, — это UB.

## 7. Правила чтения сложных объявлений

Пример из кода:

```cpp
int const** const (&x)(int(&)[10])
```

**Читаем:** `x` — **ссылка на функцию**, которая принимает **ссылку на массив из 10 `int`** и возвращает **константный указатель на указатель на константный `int`**.

### «Правило улитки»

1. Ищем **идентификатор** (`x`)
2. Идём **вправо** до закрывающей круглой скобки, читая типы
3. Идём **влево** до открывающей круглой скобки, читая типы
4. Повторяем шаги 2–3, пока не закончится запись

Разбор по шагам для примера:
- идентификатор: `x`
- влево от `x` до `(`: `&` → «ссылка на …»
- вышли из скобок, идём вправо: `(int(&)[10])` → «функция, принимающая ссылку на массив из 10 `int`»
- влево от скобок: `int const** const` → «возвращает константный указатель на указатель на константный `int`»

## 8. Заголовочные файлы и раздельная компиляция (`sqr.h`, `sqr.cpp`)

### `sqr.h`

```cpp
#ifndef MYMATH_SQR
#define MYMATH_SQR

constexpr int kConst = 10;

int Square(int x);                 // только ОБЪЯВЛЕНИЕ

template <typename T>
T SquareTemplate(T x) {            // шаблон определён ПРЯМО в заголовке
    return x * x;
}

#endif  // MYMATH_SQR
```

### `sqr.cpp`

```cpp
#include "sqr.h"

int Square(int x) {                // ОПРЕДЕЛЕНИЕ
    return x * x;
}
```

### Что здесь происходит

- **Охранные макросы (include guards):** `#ifndef MYMATH_SQR` / `#define` / `#endif` не дают заголовку **подключиться дважды** в один файл (иначе получим повторные определения). Имя макроса должно быть уникальным.
- **Объявление в `.h`, определение в `.cpp`:** это ровно «объявление vs определение» из [[C++ - Лекция 2 - Области видимости и циклы|лекции 2]] и [[C++ - Лекция 5 - Функции и ссылки|лекции 5]]. Заголовок говорит другим файлам, что `Square` существует; тело лежит в одном `.cpp` — так соблюдается ODR (определение одно).
- **Шаблон лежит в заголовке целиком.** Компилятор должен видеть тело шаблона **в месте, где он инстанцируется** (для `SquareTemplate(z)` с `double`) — поэтому шаблоны обычно определяют в `.h`, а не в `.cpp`.
- **`constexpr int kConst = 10;`** — константа времени компиляции; ею задаётся размер массива: `int arr[kConst]{};` в `main` (размер массива обязан быть константой компиляции — [[C++ - Лекция 4 - Массивы|лекция 4]]).
- `#include "mymath/sqr.h"` — кавычки для **своих** заголовков, `<...>` — для стандартных ([[C++ - Лекция 1 - Устройство программы, типы, память, условное выполнение|лекция 1]]). Путь `mymath/` значит, что `sqr.h` и `sqr.cpp` лежат в папке `mymath`.

### Сборка из нескольких файлов

```bash
g++ -std=c++20 main.cpp mymath/sqr.cpp -o main
```

Каждый `.cpp` компилируется отдельно, а **компоновщик** (линковщик) потом связывает результаты.

> [!important] Нельзя забыть `sqr.cpp` при сборке
> В `main(3).cpp` есть вызов `H(Square)` — он использует адрес функции `Square`, значит нужно её **определение**. Если собрать только `main.cpp`, сборка закончится **ошибкой компоновки** (`undefined reference to Square(int)`) — это ровно ситуация «объявил, но не определил» из [[C++ - Лекция 5 - Функции и ссылки|лекции 5]].

## Итог лекции

- Ссылку/указатель на **локальную** переменную возвращать нельзя; можно — на динамический объект, глобальный/статический, или на переданный по ссылке параметр
- **`static`**-переменная живёт всю программу, инициализируется один раз, хранит значение между вызовами
- **Перегрузка**: по числу и типам аргументов; выбирается вариант с меньшим числом преобразований (точное совпадение → promotion → conversion); `const` самого параметра игнорируется, а `const` на объекте за указателем — нет
- **Шаблоны**: компилятор порождает версии функции; выведение по значению отбрасывает `const`/ссылку и низводит массив/функцию, выведение по ссылке сохраняет `const` и **не** низводит массив
- Приведения: `static_cast` (обычные преобразования), `const_cast` (константность), `reinterpret_cast` (биты), стиль C — не использовать
- Сложные объявления читаем «улиткой»
- Заголовок: объявления + шаблоны + include guards; определения функций — в `.cpp`; при сборке нужно передать **все** `.cpp`
